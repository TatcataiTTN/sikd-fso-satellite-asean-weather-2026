# SIKD/FSO Satellite QKD — Reproducible Code Package (Paper 3, GLOBECOM 2026)

**Project:** Simultaneous Information and Key Distribution over LEO Satellite FSO Channels
**Paper:** "Towards Reliable Satellite NTN Communications with Simultaneous Information and Quantum Key Distribution under Tropical Weather Dynamics" — IEEE GLOBECOM 2026 WS-10
**Authors:** Trương Tuấn Nghĩa (USTH), TS. Vũ Quang Minh (QTALab, PTIT)
**Date:** 2026-07-11

This package supersedes the paper-1/paper-2 code snapshot previously stored at this
same path (see git history before this commit) with the current pipeline used for
Paper 3: real ten-year ERA5 weather reanalysis, a live 1,019-satellite Starlink
Shell-1 constellation, station-satellite scheduling algorithms (ALG-0/1/2), and an
inter-satellite-link relay model.

---

## Quick Start

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Run the full test suite (304 tests, ~2s)
python -m pytest tests/ -q

# 3. Regenerate all figures + provenance (skips ERA5/TLE re-fetch by default)
python scripts/run_all.py --skip-fetch

# 4. Regenerate everything including a fresh ERA5/TLE fetch (slow, needs internet)
python scripts/run_all.py
```

`scripts/run_all.py` runs every pipeline step in dependency order, checks that each
step's declared output files actually refresh (catches a script silently writing to
the wrong path), and cross-checks every number in `data/verify/*.txt` against the
paper's `main.tex` (not included in this code package — see below).

## Layout

```
modules/            Core simulation code (no __init__.py, imported via sys.path)
  channel_model.py       FSO channel: geometric loss, Beer-Lambert, Rytov turbulence
  sikd_performance.py    QKD chain: Psift, QBER, SKR (Gauss-Hermite quadrature)
  weather_model.py       3-state weather model (clear/rain/cloud), ERA5 climatology
  orbital_mechanics.py   SGP4/TLE propagation, ground-station geometry (Skyfield)
  isl_topology.py        Inter-satellite-link mesh graph from TLE orbital elements
  isl_relay.py           Multi-hop relay latency (time-optimal / capacity-optimal)
  ...                    (see modules/ for the full list)
scripts/             Pipeline scripts (01-13, numbered by rough dependency order)
  run_all.py             Master orchestration: runs everything, verifies outputs
  02_filter_shell1_tle.py .. 13_powersplit_realpass.py
tests/               pytest suite (304 tests), one file per module
data/
  raw/                 Raw ERA5/ERA5-Land hourly weather (8 ASEAN cities, 2015-2024)
  starlink_shell1_*.txt  Real Starlink Shell-1 TLE snapshots (CelesTrak)
figures/             Pre-rendered output figures (what scripts/run_all.py produces)
relay_explained/     Diagrams + writeup of the ISL relay algorithm (mermaid + README)
```

`data/intermediate/`, `data/verify/`, `data/provenance/`, and `temp/` (epoch-variant
scratch runs) are regenerated by the pipeline and intentionally not included here;
run `scripts/run_all.py` to produce them locally.

## Notes on reproducibility

- All results in the paper come from the real 1,019-satellite Starlink Shell-1
  subset (TLE in `data/starlink_shell1_real_tle.txt`, CelesTrak, retrieved
  2026-06-25) and ten years (2015-2024) of ERA5/ERA5-Land reanalysis
  (`data/raw/era5_hourly_*.csv.gz`, via Open-Meteo), not synthetic data.
- Every pipeline script writes a provenance file (timestamp, input file hashes,
  parameters, key output numbers) to `data/provenance/` when run — see
  `utils.py:save_provenance()`.
- Some scripts are epoch-sensitive (satellite identity/position depends on how far
  the simulation start time is from the TLE epoch); `scripts/run_all.py` sets the
  correct environment variables for these automatically. See the comments at the
  top of `scripts/run_all.py` for which steps require this.

## What is not in this package

The LaTeX paper source (`main.tex`, `references.bib`, figure captions) is
maintained separately and synced to Overleaf directly, not through this
repository.
